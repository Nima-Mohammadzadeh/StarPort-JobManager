# SGTIN-198 Encoding Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let an operator create standard jobs encoded as SGTIN-198 (GTIN + serial of up to 20 characters) instead of SGTIN-96, with every downstream feature working for both.

**Architecture:** The encoding is a per-job property (`jobs.epc_scheme`, `jobs.serial_format`). `generators.py` gets a scheme table and a dispatching `generate_epc` / `decode_epc`; the serial registry still counts integers, and a serial format turns the integer into the EPC serial characters only at write time. Server and both pages stop assuming a 24-hex EPC.

**Tech Stack:** Python 3.13, Flask, SQLite, openpyxl, pytest (`tests/conftest.py` `jm` fixture builds an isolated install); vanilla JS in `templates/index.html` and `templates/rewind.html`.

**Spec:** `docs/superpowers/specs/2026-11-10-sgtin-198-design.md`

## Global Constraints

- SGTIN-96 output stays byte-for-byte unchanged; jobs with no scheme column value behave as `sgtin96`.
- SGTIN-198: header `0x36` (8 bits), filter `001` (3), partition `101` (3), company prefix 24 bits + item reference 20 bits (44), serial 140 bits = 20 characters x 7-bit ASCII, zero-padded on the right; 198 bits written as **50 hex characters** (2 zero padding bits at the end).
- Serial longer than 20 characters, or a character outside 7-bit ASCII, is refused with a clear message.
- Serial registry (`serial_store.py`, `MAX_SERIAL = (1 << 38) - 1`) keeps counting integers and is not changed.
- `serial_format` allowed values: `number` only. `epc_scheme` allowed values: `sgtin96`, `sgtin198`.
- Scheme is fixed at job creation; added data uses the job's scheme.
- Scheme choice is refused for special, GO2 and CDO jobs.
- The EPC encoding choice sits behind an **Advanced** area on the New job form; SGTIN-96 is the default.
- New job columns are added with the existing `add_col` pattern in `init_db()`; no migration.
- Run tests with `python -m pytest tests -q` (pytest is installed in this container; if a fresh container, `pip install pytest -r requirements.txt`).

## Review Focus

1. A tag scanned in the wrong length for its job (24 hex on a SGTIN-198 job or 50 hex on a SGTIN-96 job) must say which encoding the job uses, not "not an EPC". (Task 5)
2. Serial `5` and serial `50` must produce different EPCs and decode back to themselves (zero padding vs the digit character `0`, which is `0x30`). (Task 1)
3. Pasted scans with lowercase, spaces, colons or a `0x` prefix must still be accepted for 50-hex EPCs, as they are for 24-hex. (Task 5)
4. The 50-hex EPC must be stored as text in the `.xlsx` (no numeric coercion in Excel) and the file must be re-read and checked after writing. (Task 2)
5. Old databases (no `epc_scheme` column) must open, and existing jobs must keep creating, adding and looking up SGTIN-96 exactly as before. (Task 3)
